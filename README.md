#### Description:
### To start, I would like to say this project was definitely not my first choice, but it was suggested to me by someone and I must say, I had a great time making it.
#### This is a gameboy platformer written in c, it uses the CrossZGB framework. So far, I've seen 3 primary ways to make gameboy games, writing them in assembly(oh god please no), using gbdk which is the framework that CrossZGB is built off of, thus being much more annoying and harder to work with, or using CrossZGB. 
#### To be honest I was going to make this project using LOVE2D, I even watched the seminar about making games with LOVE2D, and I started looking into the sources the person giving the seminar mentioned, but setting up vscode was too annoying and I quickly gave up. I then started to consider making a web app with flask, and got so hopeless to the point that I was about to just make some commandline minigames with c. I actually ended up abandoning my final project for about a month.
#### But, one day in my computer science class, I was given an opportunity, an opportunity to finally put the c experience I had gotten from this course that was collecting dust in my brain for a while through this framework.
#### CrossZGB is fairly simple, even having a template for you to start on so you don't have to make the annoying make file and a walkthrough on it's different features and functions. It was fairly simple to pick up and I was able to make this project fairly quickly. But without further ado let's start actually talking about the project itself
#### This project is made up out of 2 main parts, the sprite initializations in SpritePlayer.c, SpriteEnemy.c, SpriteEnemyStill.c, SpriteEnemyH.c and then the initilization of the game and creation of the sprites in StateGame.c and ZGBMain.c let's start with the sprites\
#### SpriteEnemyStill.c - this is the most simple sprite, it's just an enemy that stands still. If the player collides with it they are sent back to the beginning of the level
#### SpriteEnemy.c - I'll admit I could have done a better job naming these. This sprite moves vertically changing directions from up to down or down to up when it collides with a wall tile. Also sends the player back to the beginning upon colliding with them.
#### SpriteEnemyH.c - Similar to SpriteEnemy.c, but instead of moving vertically it moves horizontally, changing directions when colliding with a wall tile. Should go without saying that this one also sends player back to the beginning upon colliding with them.
#### SpriteFlag.c - This sprite also does an action upon collision with the player. When the player collides with this sprite, it sends the player back to the beginning and updates the game_score counter by one keeping track of how many times the player has beat the level.
#### SpritePlayer.c - This is the sprite the player controls. You move it with the arrow keys, it cannot move through wall tiles, as with all the other moving sprites.
#### now for the game initialzation.
#### StateGame.c - spawns the player sprite and the flag sprite, initializes the map, and initializes the HUD which has nothing except the word score followed by a number indicating how many times you have beaten the level. Whenever the player collides with an enemy or the flag, the game's state is set back to how it is initialized here.
#### ZGBMain.c - Iterates through the map, replacing the sprite stamps with their corresponding, enemies, see res/backgrounds/gb/meta/object.png for more on that. But basically, each 8x8 stamp in object.png is able to be deduced as a pointer by ZGBMain.c and is replaced with the enemy sprite the pointer corresponds to. That's the beauty of using this framework, most of the painstaking back breaking work, such as initializing sprites based on an exact position is abstracted away. To this point, I still find it amazing that ZGBMain.c can somehow tell exactly what sprite marker it is without the color. I've tried making the sprite marker look the same besides color and it's still able to differentiate between them, even though when pasting the stamp onto the map they're all the same color.
#### That's pretty much it, this project taught me a lot about computer science, as this is my first real world application of C, I can't wait to see what else is possible.  Goodbye CS50, I'll never forget how much you've taught me!
